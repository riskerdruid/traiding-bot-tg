# Бот торговых сигналов для Telegram

Следит за рынком круглые сутки и присылает в Telegram готовые сигналы:
что покупать или продавать, по какой цене входить, где выходить при
неудаче и где забирать прибыль. Каждый сигнал объясняется обычными
словами, а потом сам доводится до результата — бот показывает, сколько
раз он угадал.

Работает по двум площадкам одновременно:

* **биржа** (через `ccxt`) — золото, криптовалюта, фьючерсы;
* **Pocket Option** — бинарные опционы, в том числе круглосуточные
  OTC-пары, которые торгуются и в выходные.

Бот **не торгует**: доступа к деньгам и счетам у него нет. Он только
присылает информацию — сделку человек открывает сам.

---

## Как это выглядит для пользователя

Внизу экрана четыре кнопки, больше в боте ничего нет:

| Кнопка | Что показывает |
|---|---|
| 🎯 **Сигналы** | что сейчас в работе, чем закончились последние, жив ли бот |
| 📊 **Результаты** | сколько сигналов угадано и что это в деньгах |
| ⚙️ **Настройки** | за чем следить, как часто писать, деньги, ночной режим |
| ❓ **Помощь** | шесть коротких тем без единого термина |

Настроек ровно четыре, и все выбираются кнопками:

1. **За чем следить** — список инструментов с понятными именами
   («Золото», «Биткоин», «EUR/USD»). В списке только то, что реально
   доступно на подключённой площадке.
2. **Как часто сигналы** — три режима: «Осторожный» (1–3 в неделю),
   «Обычный» (1–3 в день), «Частые сигналы» (10–20 в день). Режим
   выставляет сразу десяток внутренних порогов — человеку их видеть
   незачем.
3. **Деньги** — сумма на счёте и риск на сделку (0.5 / 1 / 2%). Нужно,
   чтобы в каждом сигнале писать, какой брать объём.
4. **Ночной режим** — не будить с 23:00 до 7:00. Пропущенное никуда
   не денется, утром оно будет в разделе «Сигналы».

### Чего в боте намеренно нет

Это не забытое, а вырезанное — бот рассчитан на человека, который
никогда не торговал:

* нет мини-приложения с полусотней ползунков и графиков;
* нет ручной правки порогов стратегии — только выбор режима;
* нет отдельных экранов статуса, истории и новостного календаря:
  всё нужное из них сведено в одну строку на экране сигналов;
* нет будильников по цене — они путались с сигналами;
* нет переключателей уведомлений: сигналы и их результаты приходят
  всегда, а сводка за день — только если за день что-то было.

## Установка

Нужен сервер с Docker. Домен, сертификат и открытые порты **не нужны**:
бот сам звонит в Telegram и наружу ничего не слушает.

```bash
git clone https://github.com/riskerdruid/traiding-bot-tg.git /opt/trading-bot
cd /opt/trading-bot
cp .env.example .env
nano .env          # заполнить BOT_TOKEN и OWNER_IDS
./deploy.sh
```

`deploy.sh` соберёт образ, прогонит тесты и поднимет контейнер.
Дальше — открыть бота в Telegram и отправить `/start`.

### Что заполнить в `.env`

| Переменная | Что это |
|---|---|
| `BOT_TOKEN` | токен от [@BotFather](https://t.me/BotFather) |
| `OWNER_IDS` | Telegram id получателей через запятую ([@userinfobot](https://t.me/userinfobot)) |
| `EXCHANGE` | биржа из списка `ccxt`: `okx`, `binance`, `bybit`… Торговые ключи не нужны |
| `EXCHANGE_PROXY` | прокси, если биржа не открывается с сервера |
| `SYMBOLS` | за чем следить на первом запуске; дальше меняется в боте |
| `PO_SSID` | ключ Pocket Option, если нужны опционы (удобнее прислать в бота) |
| `TIMEZONE` | часовой пояс для времени в сообщениях |

Остальное в `.env` трогать не нужно: это стартовые значения стратегии
на первый запуск с пустой базой, дальше их задаёт выбранный режим.

### Запуск без Docker (для разработки)

```bash
python -m venv .venv
.venv\Scripts\activate         # Windows
source .venv/bin/activate      # Linux / macOS
pip install -r requirements.txt
cp .env.example .env
python run.py
```

```
    notifier.py        отправка сигналов с учётом ночного режима
  engine/
    scanner.py         обход инструментов, создание сигналов
    tracker.py         доведение сигналов до результата
  strategy/
    trend_momentum.py  когда давать сигнал
  market/
    feed.py            маршрутизатор между площадками
    ccxt_broker.py     биржа

    catalog.py         список инструментов для выбора в боте

```

Всё живёт в одном процессе: компонентов немного, они делят одну базу
и один клиент биржи. Разносить их по сервисам означало бы усложнить
развёртывание без выигрыша.

### Как принимается решение о сигнале

Сначала **ворота** — жёсткие условия, любое непройденное отменяет сигнал:

1. рынок трендовый, а не стоит на месте (ADX выше порога);
2. сработал вход — пересечение быстрой и медленной скользящих;
3. направление не спорит со старшим таймфреймом;
4. цена не в зоне перегрева (RSI в рабочем коридоре).

Потом **подтверждения** — каждое добавляет уверенности: согласие
старшего графика, положение цены относительно длинной средней,
перевес покупателей над продавцами, гистограмма MACD, рост силы
тренда, всплеск объёма. Сумма даёт уверенность 0–100%; порог
задаёт выбранный режим.

Стоп ставится по ATR — по реальному размаху цены, а не фиксированным
числом пунктов. Цель считается от стопа через заданное соотношение.

Анализ идёт **только по закрытым свечам**: иначе сигнал «мигал» бы
внутри свечи и не совпадал с тем, что человек видит на графике.
Одна свеча — максимум один сигнал, на инструмент — один активный
сигнал, после сигнала действует пауза.

В сообщение уходят причины **простыми словами** («цена развернулась
вверх», «покупатели сильнее продавцов»), а числовой снимок индикаторов
сохраняется в базу — он нужен только для разбора постфактум.

### Фильтр новостей

За 30 минут до важной макростатистики (США и еврозона) и 15 минут после
бот молчит: в эти минуты цену двигает новость, а не график. Календарь
берётся из недельного JSON-фида Forex Factory, кешируется в базе и
переживает недоступность источника. Настройками это не управляется —
вопрос, на который новичку нечего ответить.

### Журнал сигналов

Каждый сигнал пишется в SQLite (`data/signals.db`) со всеми уровнями,
причинами и снимком индикаторов. Трекер раз в полминуты проверяет
активные сигналы и закрывает их: цель, стоп или истёк срок. Из этих
исходов и считается статистика — она честная, потому что уровни
фиксируются в момент выдачи и потом не меняются.

## Эксплуатация

```bash
docker compose logs -f bot          # что происходит
docker compose restart bot          # перезапустить
docker compose down                 # остановить
```

Контейнер сам сообщает, здоров ли он: бот раз в полминуты обновляет
файл `data/heartbeat`, а `HEALTHCHECK` смотрит на его возраст. Если
процесс жив, но цикл событий встал, Docker это увидит.

Данные лежат в `data/` и `logs/` — они переживают пересборку образа.

### Обновление со старой версии

У предыдущей версии было мини-приложение, а рядом с ботом работал Caddy
с сертификатом. Теперь ни того, ни другого нет: после обновления контейнер
`trading-signals-caddy` остаётся висеть и отвечать ошибкой на старом домене.
Его можно убрать — порты 80 и 443 освободятся:

```bash
docker rm -f trading-signals-caddy
docker volume rm trading-bot_caddy_data trading-bot_caddy_config
```

Настройки, журнал сигналов и статистика при обновлении сохраняются.
Кнопка мини-приложения в Telegram снимается сама при первом запуске.

### Автообновление сервера

На сервере стоит таймер systemd: раз в две минуты он смотрит в git,
и если в `main` появились коммиты — собирает образ, **прогоняет тесты**
и только потом подменяет контейнер. Если новая версия не собралась,
не прошла тесты или не поднялась, откат происходит сам, а в Telegram
приходит сообщение.

Разово, на сервере от root:

```bash
bash deploy/install-autodeploy.sh
```

После этого руками деплоить не нужно: `git push` в `main` приезжает сам.

Полезное:

```bash
tail -f /var/log/trading-bot-deploy.log      # что делает автообновление
systemctl status trading-bot-deploy.timer    # жив ли таймер
/opt/trading-bot/deploy/autodeploy.sh --force   # пересобрать вручную
```

## Инструменты разработчика

```bash
# Бэктест на истории биржи — отчёт до первого живого сигнала
python -m tools.backtest --symbol "XAU/USDT:USDT" --timeframe 15m --limit 1000

# Тесты: база, статистика, трекер, стратегия, настройки,
# все тексты сообщений и все кнопки
python -m tests.test_smoke
python -m tests.test_indicators
```

`tests/test_smoke.py` — то, что автодеплой гоняет в новом образе перед
подменой работающего бота. Он не ходит в сеть и проверяет в том числе
две вещи, которые иначе всплывают только в переписке с пользователем:
что каждая кнопка ведёт в существующий обработчик и что в тексты
сообщений не просочился трейдерский жаргон.

## Бинарные опционы (Pocket Option)

Работают через неофициальный клиент `BinaryOptionsToolsV2`. Нужен ключ
сессии: в боте «⚙️ Настройки» → «📈 За чем следить» → «🔑 Подключить
опционы» — там пошаговая инструкция, как достать его из браузера.
Пароль от счёта нигде не вводится.

Ключ живёт несколько дней, потом его нужно прислать заново. Сообщение
с ключом бот удаляет из переписки сразу после проверки.

Опцион отличается от биржевой сделки: нет стопа и цели, есть направление
и срок. Сигнал считается удачным, если к моменту истечения цена ушла
в предсказанную сторону. Выплата ниже 80% почти всегда невыгодна: при
92% достаточно угадывать 52% сделок, при 70% — уже 59%.

⚠️ Лицензия `BinaryOptionsToolsV2` разрешает свободно только **личное**
использование; коммерческое требует письменного разрешения ChipaDevTeam.

## Что стоит знать о результатах

* Прибыльность не гарантируется. Стратегия может не работать на вашем
  рынке и в вашей фазе рынка.
* Статистика бота считается по идеальному исполнению: вход ровно по
  цене сигнала, без проскальзывания и комиссий. В жизни результат хуже.
* Пока завершённых сигналов меньше 20–30, цифры почти ничего не значат.
* Бот — источник информации, а не советник. Ответственность за сделки
  остаётся на том, кто их открывает.
