# Бот торговых сигналов для Telegram

Анализирует рынок, находит точки входа и присылает их в Telegram — со стопом,
целью, объёмом позиции и объяснением, почему сигнал возник. Ведёт журнал всех
сигналов и считает по ним честную статистику.

Внутри Telegram работает Mini App: живые котировки, свечной график с уровнями
сигнала, отчёты и **полная настройка бота** — инструменты, таймфреймы, пороги,
риск, фильтр новостей и уведомления.

**Бот не торгует.** Торговые API-ключи не нужны, доступа к деньгам нет.
Только анализ и уведомления — решения принимает трейдер.

---

## Два уровня настройки

Это главное, что стоит понять про проект.

| | Кто | Где | Что |
|---|---|---|---|
| **Установка** | разработчик, один раз | файл `.env` | токен бота, кому слать, домен, биржа |
| **Работа** | заказчик, когда угодно | Mini App → «Настройки» | всё остальное |

Заказчику **не нужен** ни сервер, ни SSH, ни `.env`. Инструменты, таймфреймы,
порог уверенности, ширина стопа, соотношение риск/прибыль, размер депозита,
фильтр новостей, время сводки, режим «не беспокоить» — всё меняется кнопками
в приложении и применяется **сразу, без перезапуска**.

## Установка на сервер

Нужны: сервер с публичным IP, домен, указывающий на него A-записью, и Docker.

```bash
git clone <репозиторий> && cd traiding-bot-tg
cp .env.example .env
nano .env          # заполнить BOT_TOKEN, OWNER_IDS, DOMAIN
./deploy.sh
```

`deploy.sh` проверит настройки и домен, соберёт образ, поднимет бота вместе
с Caddy, дождётся выпуска сертификата Let's Encrypt и скажет, что готово.
Никаких certbot и cron — Caddy продлевает сертификат сам.

### Что заполнить в `.env`

| Параметр | Где взять |
|---|---|
| `BOT_TOKEN` | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `OWNER_IDS` | заказчик пишет [@userinfobot](https://t.me/userinfobot), тот присылает id |
| `DOMAIN` | ваш домен, например `traiding-bot.example.ru` |
| `WEBAPP_URL` | `https://` + тот же домен |

Остальное имеет рабочие значения по умолчанию.

### Если на сервере уже есть свой реверс-прокси

`deploy.sh` и профиль `caddy` рассчитаны на чистый сервер, где 80 и 443
свободны. Если там уже стоит nginx с другими сайтами, Caddy поднимать
**не нужно** — вместо него добавьте vhost к существующему прокси:

```bash
# 1. Бот слушает только локальный адрес, наружу порт не публикуется
#    (в .env)
BIND_HOST=192.168.1.1
BIND_PORT=8097

# 2. Запуск без профиля caddy
docker compose up -d bot

# 3. Готовый vhost для nginx — в deploy/nginx-vhost.conf
#    Поправьте домен и адрес бэкенда, положите в conf.d, перезагрузите nginx
```

Сертификат выпускается в два шага: сначала HTTP-only vhost с одной локацией
`/.well-known/acme-challenge/`, потом `certbot certonly --webroot`, потом полный
конфиг с TLS. Одним шагом не выйдет — nginx не стартует с ссылкой на ещё
не существующий сертификат.

**Две вещи, на которых легко споткнуться:**

* **Сборка образа падает с `Failed to resolve pypi.org`.** У buildkit своя сеть,
  и на серверах со строгим firewall она не достаёт до DNS. Собирайте через сеть
  хоста: `docker build --network=host -t trading-signals-bot .` — compose потом
  подхватит готовый образ по имени.
* **Контейнер не видит Telegram.** Docker-подсети обычно ходят в интернет
  напрямую, минуя VPN хоста. Если Telegram у вас блокируется, подсеть контейнера
  нужно завернуть в VPN — и тогда её стоит зафиксировать в compose
  (`BOT_SUBNET`), иначе после пересоздания сети правило перестанет совпадать.

### Запуск без Docker (для разработки)

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux / macOS
pip install -r requirements.txt
python run.py
```

Бот сам проверит настройки при старте и понятно скажет, чего не хватает.

Чтобы открыть Mini App в обычном браузере, поставьте `WEBAPP_DEV_MODE=true`
и зайдите на `http://localhost:8080`.

> **Безопасность.** Каждый запрос к API проверяет подпись Telegram, поэтому
> посторонний не увидит сигналы, даже зная адрес. `WEBAPP_DEV_MODE=true`
> эту проверку отключает — в рабочем режиме он **обязан** быть `false`.

### Как добавить новый параметр в настройки

Одна строка в `app/storage/settings_store.py`:

```python
Field("my_param", "int", "Подпись для заказчика", "strategy",
      hint="Что это значит простыми словами", minimum=1, maximum=100),
```

Дальше он сам появится в Mini App с нужным типом контрола, границами
и проверкой. Вёрстку править не нужно — интерфейс строится из описания.

### Как принимается решение о сигнале

Логика разделена на жёсткие **ворота** и накопительные **подтверждения**.

**Ворота** — если не выполнено хотя бы одно, сигнала не будет:

1. `ADX ≥ минимума` — рынок должен быть трендовым. В боковике трендовые
   входы систематически теряют, поэтому там бот молчит.
2. Пересечение быстрой и медленной EMA — сам триггер входа.
3. Направление не спорит со старшим таймфреймом.
4. RSI в рабочей зоне — не входим в уже перегретое движение.

**Подтверждения** добавляют уверенности (0–100%): согласие старшего ТФ,
положение цены относительно EMA тренда, +DI/−DI, гистограмма MACD, растущий
ADX, объём выше среднего. Сигнал отправляется, только если набралось не
меньше порога.

**Уровни.** Стоп ставится по ATR — по реальной волатильности инструмента,
а не фиксированным числом пунктов. Цель считается от стопа через
соотношение риск/прибыль. **Объём позиции** считается от депозита и
допустимого риска: сколько брать, чтобы на стопе потерять ровно заданный
процент.

### Фильтр новостей

Золото резко ходит на макростатистике США — NFP, CPI, решения ФРС.
Технический сигнал за минуту до такой публикации почти бесполезен: цену
двинет новость, а не график.

Бот загружает экономический календарь и молчит в окне вокруг важных событий.
Источник публичный, ключ не нужен. При недоступности сети используется
последний загруженный календарь.

### Журнал сигналов

Каждый сигнал доводится до исхода: **цель**, **стоп** или **истёк по времени**.
Отсюда берётся winrate, профит-фактор и результат в единицах риска (R).

Две особенности расчёта, сделанные сознательно:

* **Если внутри одной свечи задеты и цель, и стоп — засчитывается стоп.**
  По свечным данным нельзя узнать, что произошло раньше, и честнее занизить
  статистику, чем показать заказчику winrate, который не повторится вживую.
* **Профит-фактор считается в единицах риска, а не в процентах цены.**
  Риск на сигнал одинаков, а ATR-стоп в процентах каждый раз разный —
  деление процентов дало бы цифру, противоречащую среднему R.

## Справка внутри продукта

Заказчику не нужно читать этот файл: вся справка встроена в продукт.

* **В приложении** — кнопка «?» в шапке. Темы раскрываются по нажатию,
  внутри пошаговые инструкции, примеры и предупреждения.
* **В боте** — команда `/help` или кнопка «Помощь»: те же тексты
  сообщениями, с переходами между темами.

Обе поверхности берут тексты из одного места — `app/help.py`. Добавить
тему можно одной записью, править вёрстку не нужно:

```python
{
    "id": "my-topic",
    "icon": "💡",
    "title": "Заголовок",
    "summary": "Одна строка для меню",
    "blocks": [_t("абзац"), _steps("шаг", "шаг"), _warn("важное")],
}
```

Разобранные темы: с чего начать, как читать сигнал по бирже и по опциону,
**как получить SSID Pocket Option**, как добавить инструменты, что делает
каждая настройка, как читать статистику, зачем фильтр новостей, что делать
при сбоях и честные ограничения продукта.


`restart: unless-stopped` поднимет бота после перезагрузки сервера или сбоя.

`GET /api/health` отвечает `200`, пока сканер работает, и `503`, если нет.
Приватных данных не отдаёт — можно направить на внешний монитор, чтобы
узнавать о падении не по тишине в чате.

## Что стоит знать о результатах

**Бэктест — не обещание.** Проверка на прошлых данных показывает, как
стратегия вела бы себя в тех рыночных условиях. Другой рынок — другой
результат.

**Выборка должна быть достаточной.** По 10–15 сигналам winrate не значит
ничего. Ориентируйтесь минимум на 30–50 завершённых. Бот сам предупреждает
об этом, пока выборка мала.

**Трендовая стратегия однобока в одностороннем рынке.** Если инструмент
уверенно падает, фильтр старшего таймфрейма будет отсекать все покупки —
это задуманное поведение, а не сбой.

## Расширение

**Своя стратегия.** Унаследуйтесь от `Strategy` в `app/strategy/base.py`,
реализуйте `analyze()` и подставьте класс в `app/engine/scanner.py`.
Журнал, уведомления, статистика и Mini App продолжат работать без изменений.

**Другие рынки.** Инструменты выбираются в приложении из списка биржи;
биржа задаётся в `.env` — любая из поддерживаемых ccxt.

**Новая площадка.** Реализуйте `BrokerAdapter` из `app/market/base.py`
и зарегистрируйте её в `app/market/feed.py`. Остальной код — стратегия,
журнал, статистика, Mini App — заработает с ней без изменений.

## Бинарные опционы (Pocket Option)

Кроме бирж бот умеет работать с брокером бинарных опционов. Это **другой
вид сделки**, и он честно отражён в интерфейсе:

| | Биржа | Бинарный опцион |
|---|---|---|
| Что открывается | позиция | ставка на направление |
| Как закрывается | стоп или цель | по истечении срока |
| Результат | движение цены | выплата брокера или вся ставка |
| Метрика | R от расстояния до стопа | R от процента выплаты |

**Зачем отдельный источник данных.** Котировки OTC-пар (`EURUSD_otc`
и подобных) брокер генерирует сам: они идут и в выходные, и получить их
со стороны нельзя. Считать индикаторы по настоящему EUR/USD и выдавать
сигнал по OTC-графику — значит показывать трейдеру цифры, которых нет
у него на экране. Поэтому данные берутся у самого брокера.

### Как включить

1. Установите пакет: он уже в `requirements.txt`
2. Войдите в Pocket Option в браузере и скопируйте **SSID** сессии
3. В Mini App → «Настройки» → «Бинарные опционы» вставьте SSID
4. Там же добавьте активы: в окне выбора инструментов появится вкладка
   «Опционы» с активами, их выплатой и меткой OTC

Инструменты адресуются префиксом площадки, так что биржа и опционы
работают одновременно:

```
XAU/USDT:USDT   — золото на бирже
po:EURUSD_otc   — OTC-пара у брокера
```

### Настройки раздела

| Параметр | Смысл |
|---|---|
| SSID сессии | Токен входа. Живёт ограниченное время — при отказе получите новый |
| Срок опциона | Через сколько минут истекает сделка |
| Минимальная выплата | Сигналы по активам с низкой выплатой не отправляются |
| Только OTC-активы | Оставить лишь те, что торгуются в выходные |

В карточке сигнала бот показывает **порог безубытка**: при выплате 85%
нужно угадывать 54% сделок, только чтобы не терять. Это та арифметика,
из-за которой обещания «90% winrate» в подобных проектах невыполнимы.

### Ограничения — прочитайте до запуска

* **Лицензия.** Библиотека `BinaryOptionsToolsV2` разрешает свободно
  только **личное, некоммерческое** использование. Коммерческое требует
  письменного разрешения ChipaDevTeam ([их Discord](https://discord.gg/p7YyFqSmAz)).
  Если проект платный — получите разрешение или откажитесь от этого модуля:
  без пакета бот работает по биржам как обычно.
* **Официального API у брокера нет.** Библиотека держится на
  реверс-инжиниринге веб-сокета и может перестать работать после
  обновления платформы.
* **Правила брокеров** обычно запрещают автоматический доступ. Риск
  блокировки аккаунта лежит на владельце аккаунта.
* **Бот и здесь не торгует** — методы `buy`/`sell` библиотеки не
  используются, берутся только котировки и справочник активов.
